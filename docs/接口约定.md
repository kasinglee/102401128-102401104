# 第一阶段数据接口约定

以下 API 已实现于 `js/core.js` 和 `js/storage.js`。两文件在浏览器中作为普通脚本按顺序加载；Node 可用 `require()` 导入，便于最后编写单元测试。浏览器全局名称分别为 `LostFoundCore`、`LostFoundStorage`。

## 物品字段

```js
{
  id: "唯一编号", ownerId: "发布者在本浏览器的编号",
  type: "lost" | "found", name: "物品名称", location: "地点",
  date: "YYYY-MM-DD", time: "HH:mm", description: "补充描述",
  contact: "QQ 或校内账号", imageData: "可选的图片 data URL",
  status: "寻找中" | "招领中" | "已找回" | "已归还",
  createdAt: "ISO 发布时间"
}
```

演示物品的 `ownerId` 固定为 `demo`，不可在“我的发布”中修改。新发布物品的 `ownerId` 为当前浏览器生成的 `clientId`。这仅提供单浏览器的发布者区分，不是跨设备身份认证。

## 页面可调用的仓库接口

```js
const store = LostFoundStorage.createStore(window.localStorage);
store.getItems();                  // 所有物品的副本
store.list({ type: "all", query: "耳机", location: "东3" });
store.getItem("demo-earbuds");   // 找不到时为 null
store.getMyItems();                // 当前浏览器发布的信息
store.publish(draft);             // { item, errors, saved }；校验或保存失败不会新增
store.finish(id);                 // { items, item, error }；只有 ownerId 匹配才能结束
store.subscribe(() => { /* 重新渲染 */ });
store.reload();                   // 其他标签页修改 localStorage 后可调用
```

`list()` 默认把进行中的信息排在已结束信息之前，再按发布时间倒序；搜索范围包含名称、描述和地点。可传 `type: "lost"` 或 `"found"`、`ownerId`、`includeFinished: false`。纯逻辑函数可直接调用 `LostFoundCore.validateDraft()`、`listItems()`、`finishItem()` 等。

`js/app.js` 负责页面。第二阶段可新增 `js/pages/search.js`、`detail.js`、`my-posts.js`，再在页面导航中接入，不应另建一套物品数据。最终请在 Chrome 中以 `file://` 直接打开 `index.html` 验证。
