请在你自己的 GitHub 账号下 **fork** 公开仓库 <https://github.com/kasinglee/102401128-102401104>，从主仓库最新 `main` 开始开发，完成后向主仓库 `main` 发起 **Pull Request**。不要直接推送主仓库，也不要重做李嘉星已完成的首页、发布表单和数据保存。你负责搜索、详情、“我的发布”与状态更新。请先阅读 `README.md`、`docs/分工与PSP.md`、`docs/接口约定.md` 和 `prototype/App.tsx` 中对应页面，再动代码。

## 现有项目与不可破坏的约束

这是无构建步骤的静态网页。测试人员下载仓库后必须能在 **Google Chrome 直接打开根目录 `index.html`**；不要引入需要安装依赖或启动服务器才能运行的框架、ES module、远程 CDN 或后端。脚本按 `js/core.js` → `js/storage.js` → `js/app.js` 顺序以普通 `<script defer>` 加载。可新增 `js/pages/search.js`、`detail.js`、`my-posts.js`，将新脚本放在 `js/app.js` 后面加载。样式写进 `css/style.css`，兼顾手机宽度和 PC Chrome。

当前首页可浏览预设及新发布信息，发布表单会校验并将数据保存在当前浏览器 `localStorage`。首页卡片已能进入只有标题、返回、首页按钮的空白详情页；底部有“首页 / 发布 / 我的”三入口，“我的发布”目前也是空白页。不要把 `prototype/App.tsx` 的 React 代码直接复制到正式网页；它只用于参考页面信息层级、标签和流程。

全站共用 `LostFoundApp.store`，不要另建数据数组或另用一套存储。常用接口：

```js
const { store, core, params, escapeHtml, navigate, showToast, refresh } = ctx;
store.list({ query: "耳机", type: "all", location: "" }); // 搜索名称、描述、地点；进行中排前
store.getItem(params.itemId);                           // 不存在时为 null
store.getMyItems();                                     // 当前浏览器发布的记录
store.finish(itemId);                                   // 只允许当前浏览器的发布者结束记录
core.isFinished(item);
```

`LostFoundApp.registerPage("detail", { render(ctx) { ... }, mount(ctx) { ... } })` 可覆盖空白页；`my-posts` 同理。`render` 返回页面 HTML 字符串，`mount` 在页面插入 DOM 后绑定事件。凡来自物品名称、描述、地点、联系方式、关键词等用户输入的字符串，插入 `innerHTML` 前必须使用 `ctx.escapeHtml()`；也可以用 `textContent`。原型不是实际身份认证：当前项目只能区分本浏览器创建的记录，不能宣称能在不同设备间共享信息或验证真实身份。不要新增假密码登录。

## 按顺序完成的功能

### 1. 搜索页与入口

- 在首页加一个清楚可点击的搜索入口，调用 `navigate("search")`；不要破坏首页现有分类筛选或发布按钮。
- 新增搜索页：输入关键词后点“搜索”或按 Enter 都能提交；去掉首尾空格后查询。搜索范围为物品名称、补充描述、地点，使用 `store.list({ query })`，不可只对三条演示记录写死结果。
- 显示结果数量与关键词；没有匹配项时显示明确的无结果状态和“修改关键词”入口；空白或纯空格输入不应变成“找到全部”。
- 可加入类型筛选和地点筛选作为附加特点，但先保证基本关键词搜索可用。进行中记录排在已结束记录之前；已结束记录保留并标明状态。
- 搜索结果卡片能点开对应详情。进入详情再返回搜索时，保留上次输入的关键词、筛选条件和结果；可把搜索状态保存在 `search.js` 的模块作用域。必要时修改当前详情返回逻辑，把 `fromParams` 一并带回。

### 2. 完成详情页

- 用真实物品 ID 从 `store.getItem(ctx.params.itemId)` 取数据。展示类型、当前状态、名称、地点、发生日期时间、补充描述、发布时间、可选图片。列表与详情必须读取同一条数据；物品找不到时给出友好返回入口。
- 保留现有返回按钮与“首页”按钮。返回应去进入详情前的页面：首页进入回首页；搜索进入回搜索且保留搜索条件；从“我的发布”进入回“我的发布”。
- 联系方式默认折叠，点击“查看联系方式”后显示该条信息的 QQ/校内账号及核对物品特征的提示。不要实现即时聊天或展示真实个人资料。
- 状态更新后再次打开详情应显示最新状态；已结束记录仍可查看。

### 3. 完成“我的发布”与状态更新

- 用 `store.getMyItems()` 列表显示本浏览器新发布的信息。预设演示记录的 `ownerId` 是 `demo`，不应混进“我的发布”。没有记录时显示空状态及“去发布”按钮。
- 寻物进行中显示“标记已找回”，招领进行中显示“标记已归还”。点击时调用 `store.finish(id)`，根据返回的 `error` 显示失败原因，根据返回的 `item.status` 显示成功反馈。
- 更新后该页卡片、首页、搜索和详情应显示同一新状态。已结束记录保留，但不再提供重复结束按钮；不要直接删除记录。
- 可从“我的发布”的卡片进入对应详情。任何可见按钮都应确实有响应，不能只画出样式。

### 4. 附加特点与文档

- 核心功能稳定后可做“一键复制联系方式”（若浏览器剪贴板 API 不可用，应提供可选择复制的降级方式，并且不要误报复制成功）及地点/类型筛选。它们不能挤掉核心流程。
- 更新 `README.md` 的实际目录和操作说明，说明搜索、详情、“我的发布”、状态维护怎样复现，以及本地 `localStorage` 的限制。若修改了页面或数据接口，也同步更新 `docs/接口约定.md`。
- 不要预填 PSP 实际工时、访谈、试用反馈、队友评价或测试通过截图；只记录真实发生的结果。
