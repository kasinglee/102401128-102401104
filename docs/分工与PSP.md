# HW4 结对分工与 PSP 预估

记录时间：2026-09-29，开始 HW4 编码前。以下为**顺序开发分工和预估**，须与队友核对；实际耗时、完成情况和结对评价在工作发生后记录，不能预填。

## 实现目标与范围

- 交付 PC 端网页，测试人员下载全部文件后用 Google Chrome 打开 `index.html` 即可使用核心功能。
- 核心路径：发布寻物或招领 → 浏览或按关键词搜索 → 查看详情与联系方式 → 发布者在“我的发布”改为“已找回”或“已归还” → 公共页面看到更新后的状态。
- 先完成浏览、发布、搜索、详情、状态更新及异常提示，再决定是否加入类别/地点筛选、一键复制联系方式等附加特点。
- 不把原型里的单人会话演示误写成真实身份验证；程序设计时明确数据保存和发布者的判定规则，并写进 README。

## 交付顺序与提交节点

1. 李嘉星建立网页骨架和数据接口，完成首页、发布、表单校验与保存；每完成功能至少一次 commit，推送到主仓库。
2. 李嘉星通知李莹莹第一阶段代码已就绪；李莹莹此时 fork 最新主仓库，在 fork 中依次完成搜索、详情、联系方式、“我的发布”及状态更新，按功能 commit。
3. 李莹莹发起一次汇总第二阶段功能的 Pull Request；李嘉星审查、联调并合并。若审查中发现问题，仍在该 PR 中修正。
4. 合并后开展交叉测试：双方可以测试或修复对方负责的功能，保留测试用例、运行结果及修复 commit。此阶段不要求再走 PR；若李莹莹需直接推送主仓库，仓库所有者须先授予她协作者写入权限。
5. 最后更新 README 的实际目录与运行步骤，整理博客、GitHub 提交/PR 截图和双方 PSP 实际工时。
